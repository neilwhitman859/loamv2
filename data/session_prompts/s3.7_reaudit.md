## Instructions

Run each of the 9 expert audits below **sequentially**. For each expert:

1. **State the expert name and scope** (1 line)
2. **Query the DB or read files** to establish current ground truth
3. **Check Sprint 2 findings for this expert** — for each finding, classify as:
   - **FIXED** — the fix landed and is verified (cite evidence)
   - **PARTIAL** — partially addressed, remaining work described
   - **DEFERRED** — explicitly deferred to Sprint 4+ (per plan.md)
   - **MISSED** — should have been fixed in Sprint 3 but wasn't
   - **REGRESSED** — was OK in Sprint 2, now worse
4. **Surface NEW findings** not in Sprint 2 (new bugs, new drift, things revealed by the fixes)
5. **Produce a summary** with P0/P1/P2/P3 counts (NEW + MISSED + REGRESSED only — don't re-count DEFERRED or FIXED)

**Severity definitions (same as Sprint 2):**
- **P0:** Broken, correctness-critical, or user-visible damage
- **P1:** Significant gap, must fix before enrichment (Sprint 5)
- **P2:** Improvement, not blocking
- **P3:** Nice to have

## Critical Rules

1. **READ-ONLY.** Do not fix anything. Do not write to the database. Do not edit code. This is a measurement session.
2. **Evidence-based.** Every claim must cite a query result, grep output, or file read.
3. **Delta-focused.** Don't re-describe Sprint 2 findings in full. Reference them by ID (e.g., "S2.1 F3") and state the disposition.
4. **Honest.** If a fix was incomplete or introduced a new issue, say so plainly. The point is to know where we stand, not to validate Sprint 3.
5. **Actionable verdict.** The synthesis must end with a clear recommendation the user can act on immediately.
